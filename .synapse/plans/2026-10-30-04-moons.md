# Planet-relative moons implementation plan

**Goal:** Provide #9's planet-relative moon initialization, live insertion, and inspectable physically evolved motion.

**Architecture:** Treat a moon as an ordinary positive-mass authored body with a planet-relative initial condition. Reuse the shared placement/vector editor, then resolve into the same unrestricted Newtonian state; parent association remains metadata for initialization and inspection.

**Tech Stack:** Python, NumPy, Matplotlib, existing sourced catalog and Yoshida solver, pytest.

## Global Constraints

- “Its initial parent association does not pin it in place or force it to remain bound.”
- “Live insertion follows #5: pause for placement, preserve existing bodies' positions/velocities and elapsed time, then let gravity respond when evolution continues.”
- “3D, tides, and planet formation remain outside scope.”
- Requires plan 2. Sequence after plan 3 because both adapt shared authoring files. Reuse catalog provenance rather than copying physical constants into UI code.
